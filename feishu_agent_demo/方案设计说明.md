# 采购多Agent虚拟组织系统 方案设计说明

## 一、方案概述
本方案面向采购业务，构建了 4 个可协同的 AI Agent，并基于飞书多维表格实现全链路数据沉淀、状态流转与可审计追踪。系统采用状态触发型编排，覆盖从需求解析、供应商选型、下单追踪到效能分析的完整闭环。

### 核心能力覆盖
✅ **虚拟员工建模**：4 个采购角色 Agent，职责清晰  
✅ **业务系统构建**：4 张业务表 + 表间关联关系  
✅ **业务运行与协同**：按状态自动触发，非线性流程可扩展  
✅ **审计与风控**：全操作日志入库，可追溯  

## 二、数据表设计

### 2.1 采购需求表（Demands）
用于存储原始采购指令、预算、优先级和需求状态。

关键字段（示例）：
- `demand_code`（主键）
- `source_instruction`
- `category`
- `item_name` / `spec` / `quantity` / `uom`
- `budget_amount` / `currency`
- `priority`
- `status`（待规划、已选型、已下单等）
- `recommended_suppliers`（关联 `Suppliers`，多对多）

### 2.2 供应商库（Suppliers）
用于存储供应商基础档案与准入能力。

关键字段（示例）：
- `supplier_name`（主键）
- `supplier_code`
- `credit_score`
- `main_business`（多选）
- `supplier_level`
- `status`
- `recommended_for_demands`（关联 `Demands`，多对多）

### 2.3 采购订单表（Orders）
用于承接选型结果，跟踪履约和物流状态。

关键字段（示例）：
- `order_code`（主键）
- `demand`（关联 `Demands`，一对一）
- `supplier`（关联 `Suppliers`，多对一）
- `order_amount` / `currency`
- `order_status`
- `logistics_status`（待发货、运输中、异常、已送达）
- `expected_delivery_date`
- `exception_reason`

### 2.4 运行日志表（Audit_Logs）
用于记录所有 Agent 的行为轨迹与结果。

关键字段（示例）：
- `log_id`（主键）
- `timestamp`
- `agent_name`
- `action`
- `target_table` / `target_record_id`
- `result` / `error_code`
- `message` / `detail_json`
- `demand` / `supplier` / `order`（可选关联）

## 三、Agent 角色设计

### 3.1 PlannerAgent（需求规划员）
- **职责**：解析非结构化采购指令，生成结构化需求上下文
- **输入**：`Demands.source_instruction`
- **输出**：需求状态推进（`待规划 -> 已选型`），并记录审计日志

### 3.2 SourcingAuditorAgent（选型审计官）
- **职责**：做供应商候选筛选、资质审查与比价决策
- **输入**：需求记录（优先使用 `recommended_suppliers`，缺失时按 `category` 匹配 `Suppliers.main_business`）
- **输出**：创建 `Orders` 订单，需求推进到 `已下单`，并记录审计日志

### 3.3 TrackerAgent（物流追踪员）
- **职责**：追踪物流状态，处理异常重试与终态收敛
- **输入**：`Orders.logistics_status`
- **输出**：状态更新（待发货/运输中/异常/已送达），异常时累计重试次数并记录日志

### 3.4 StrategyAgent（采购策略分析师）
- **职责**：聚合需求与订单数据，生成效能指标和风险摘要
- **输入**：全量 `Demands`、`Orders`
- **输出**：KPI 仪表摘要写入 `Audit_Logs`

## 四、业务流程设计（状态触发型）
```text
Demands.status = 待规划
        │
        ▼
PlannerAgent 解析需求并推进状态 -> 已选型
        │
        ▼
SourcingAuditorAgent 选供应商 + 创建 Orders -> Demands.status = 已下单
        │
        ▼
TrackerAgent 追踪 Orders.logistics_status
   待发货 -> 运输中 -> 已送达
              └-> 异常（重试/收敛策略）

定期触发：
StrategyAgent 聚合输出采购效能与风险摘要
```

## 五、技术架构
```text
主程序入口：main.py (AgentOrchestrator)
    ├─ Agent层：Planner / SourcingAuditor / Tracker / Strategy
    ├─ 数据访问层：FeishuBitableToolbox (requests + token缓存 + CRUD + 429重试)
    └─ 配置层：config.py (.env + 状态枚举 + 表ID)

外部系统：
飞书多维表格 OpenAPI（Demands / Suppliers / Orders / Audit_Logs）
```

## 六、部署与运行说明

### 6.1 环境准备
1. Python 3.10+
2. 安装依赖：`pip install -r requirements.txt`

### 6.2 配置说明
1. 复制 `.env.example` 为 `.env`
2. 填写：
   - `FEISHU_APP_ID`
   - `FEISHU_APP_SECRET`
   - `BITABLE_APP_TOKEN`
3. 确认 `config.py` 中 `TABLE_IDS` 对应当前 Base 的 4 张表

### 6.3 初始化与运行
1. 建字段（按 schema）：`python script/sqlinit.py`
2. 注入测试数据：`python script/inject_mock_data.py`
3. （可选）清理需求仅保留单条：`python script/clean_demands.py`
4. 启动编排器：`python main.py`

## 七、当前实现要点与后续扩展

### 7.1 当前实现要点
- 鉴权：`tenant_access_token` 自动缓存与过期刷新
- 健壮性：HTTP 429 指数退避重试
- 审计：统一 `log_to_audit_table()` 记录 Agent 操作
- 关联字段：支持 Link 字段写入与读取规范化

### 7.2 后续扩展建议
- 对接真实价格引擎与评分模型（替换当前简化策略）
- 引入 SLA 与交期偏差分析（提前预警）
- 增加飞书消息通知与异常工单自动派发
- 输出可视化看板（按部门/品类/供应商维度）
