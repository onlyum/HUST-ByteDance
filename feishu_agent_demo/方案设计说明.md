# 内容创作多Agent虚拟组织系统 方案设计说明

## 一、方案概述
本方案完全符合比赛要求，构建了一个由4个AI Agent组成的内容创作虚拟组织，通过飞书多维表格进行数据沉淀和状态管理，实现完整的业务流程自动化。

### 核心能力覆盖
✅ **虚拟员工建模**：4个Agent角色，职责清晰，协作关系明确  
✅ **业务系统构建**：2张核心业务表，完整的实体建模和表间关系  
✅ **业务运行与协同**：完整的流程链路，状态自动流转  
✅ **数据分析与报告**：定期自动生成运营分析报告  

## 二、数据表设计
### 2.1 选题任务表（content_tasks）
| 字段名称 | 字段类型 | 说明 |
|---------|---------|------|
| task_id | 单行文本 | 任务唯一ID（主键） |
| task_title | 单行文本 | 选题标题 |
| task_requirement | 多行文本 | 选题具体要求 |
| content_type | 单选 | 内容类型（公众号文章/短视频脚本/海报文案/朋友圈文案） |
| priority | 单选 | 优先级（高/中/低） |
| task_status | 单选 | 任务状态（待分配/待创作/待审核/待发布/已完成/已驳回） |
| creator_agent | 单行文本 | 分配的创作者Agent |
| auditor_agent | 单行文本 | 分配的审核员Agent |
| publisher_agent | 单行文本 | 分配的发布员Agent |
| created_at | 日期时间 | 任务创建时间 |
| deadline | 日期 | 截止时间 |
| final_score | 数字 | 最终评分（满分100） |

### 2.2 内容数据表（content_records）
| 字段名称 | 字段类型 | 说明 |
|---------|---------|------|
| content_id | 单行文本 | 内容唯一ID（主键） |
| task_id | 关联记录 | 关联对应任务ID（关联content_tasks表） |
| writer_agent | 单行文本 | 创作Agent标识 |
| content_text | 多行文本 | 生成的内容正文 |
| audit_result | 单选 | 审核结果（通过/驳回/修改后通过） |
| audit_comment | 多行文本 | 审核意见 |
| audit_time | 日期时间 | 审核时间 |
| publish_url | 单行文本 | 发布链接 |
| publish_time | 日期时间 | 发布时间 |
| view_count | 数字 | 阅读/播放量 |
| quality_score | 数字 | 内容质量评分 |

## 三、Agent角色设计
### 3.1 内容创作者Agent (ContentWriterAgent)
- **职责**：根据选题要求生成符合要求的内容
- **输入**：任务标题、任务要求、内容类型
- **输出**：生成的内容文本、质量评分
- **协作关系**：接收分配的任务，完成后提交给审核员Agent

### 3.2 内容审核Agent (ContentAuditAgent)
- **职责**：审核内容的合规性、质量和匹配度
- **输入**：生成的内容、质量评分
- **输出**：审核结果、审核意见
- **协作关系**：审核创作者提交的内容，通过的提交给发布员Agent，不通过的驳回

### 3.3 运营发布Agent (ContentPublisherAgent)
- **职责**：将审核通过的内容优化后发布
- **输入**：审核通过的内容
- **输出**：发布链接、发布时间、阅读量
- **协作关系**：接收审核通过的内容，完成发布后标记任务为已完成

### 3.4 数据分析Agent (DataAnalysisAgent)
- **职责**：定期分析业务数据，生成运营报告
- **输入**：所有任务数据、所有内容数据
- **输出**：运营周报、数据指标、优化建议
- **协作关系**：独立运行，定期生成分析报告

## 四、业务流程设计
```
┌─────────────┐
│  新建任务   │  用户/运营在多维表格中新建选题任务
└──────┬──────┘
       ↓
┌─────────────┐
│  待分配     │  系统自动分配三个Agent角色
└──────┬──────┘
       ↓
┌─────────────┐
│  待创作     │  创作者Agent生成内容
└──────┬──────┘
       ↓
┌─────────────┐
│  待审核     │  审核员Agent审核内容
└──────┬──────┘
       ├───────────────┐
       ↓  通过/修改通过  ↓  驳回
┌─────────────┐ ┌─────────────┐
│  待发布     │ │  已驳回     │
└──────┬──────┘ └─────────────┘
       ↓
┌─────────────┐
│  发布中     │  发布员Agent发布内容
└──────┬──────┘
       ↓
┌─────────────┐
│  已完成     │  任务完成，更新最终评分
└─────────────┘

定期触发：
┌─────────────┐
│ 数据分析    │  数据分析Agent每天生成运营报告
└─────────────┘
```

## 六、部署与运行说明
### 6.1 环境准备
1. 安装Python 3.10+
2. 安装依赖：`pip install -r requirements.txt`

### 6.2 配置说明
1. 复制`.env.example`为`.env`
2. 填写飞书应用凭证：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`
3. 填写多维表格配置：`BITABLE_APP_TOKEN`、`TASK_TABLE_ID`、`CONTENT_TABLE_ID`
4. 其他配置保持默认即可

### 6.3 运行系统
```bash
python main.py
```
或者直接双击运行`运行.bat`

### 6.4 测试流程
1. 在多维表格的任务表中新建一条任务，状态设置为「待分配」
2. 系统会自动分配Agent，状态变为「待创作」
3. 创作者Agent自动生成内容，状态变为「待审核」
4. 审核员Agent自动审核内容，根据质量评分决定下一步状态
5. 如果通过，状态变为「待发布」，发布员Agent自动发布
6. 最终状态变为「已完成」
7. 系统每天自动生成数据分析报告

## 七、扩展说明
### 7.1 接入真实大模型
在`agent_logic.py`的`_call_llm`方法中，实现国内大模型（豆包/通义千问/文心一言）的调用逻辑即可。

### 7.2 优化Agent分配策略
当前是固定分配，可以扩展为基于Agent负载、技能标签的智能分配策略。

### 7.3 增加飞书消息通知
可以扩展能力，将任务状态变化、审核结果等通过飞书消息通知相关人员。

### 7.4 报告自动推送
数据分析报告可以自动推送到飞书群或者保存到多维表格中。
