# 采购多Agent虚拟组织系统 方案设计说明

## 一、方案概述
本方案面向采购业务，构建了 4 个可协同的 AI Agent，并基于飞书多维表格实现全链路数据沉淀、状态流转与可审计追踪。系统采用状态触发型编排，覆盖从需求解析、供应商选型、下单追踪到效能分析的完整闭环。

### 核心能力覆盖
✅ **虚拟员工建模**：4 个采购角色 Agent，职责清晰  
✅ **业务系统构建**：4 张业务表 + 表间关联关系  
✅ **业务运行与协同**：按状态自动触发，非线性流程可扩展  
✅ **审计与风控**：全操作日志入库，可追溯  

## 二、数据表设计

### 2.1 采购需求表（Demands）
用于存储原始采购指令、预算、优先级和需求状态。

关键字段（示例）：
- `demand_code`（主键）
- `source_instruction`
- `category`
- `item_name` / `spec` / `quantity` / `uom`
- `budget_amount` / `currency`
- `priority`
- `status`（待规划、已选型、已下单等）
- `recommended_suppliers`（关联 `Suppliers`，多对多）

### 2.2 供应商库（Suppliers）
用于存储供应商基础档案与准入能力。

关键字段（示例）：
- `supplier_name`（主键）
- `supplier_code`
- `credit_score`
- `main_business`（多选）
- `supplier_level`
- `status`
- `recommended_for_demands`（关联 `Demands`，多对多）

### 2.3 采购订单表（Orders）
用于承接选型结果，跟踪履约和物流状态。

关键字段（示例）：
- `order_code`（主键）
- `demand`（关联 `Demands`，一对一）
- `supplier`（关联 `Suppliers`，多对一）
- `order_amount` / `currency`
- `order_status`
- `logistics_status`（待发货、运输中、异常、已送达）
- `expected_delivery_date`
- `exception_reason`

### 2.4 运行日志表（Audit_Logs）
用于记录所有 Agent 的行为轨迹与结果。

关键字段（示例）：
- `log_id`（主键）
- `timestamp`
- `agent_name`
- `action`
- `target_table` / `target_record_id`
- `result` / `error_code`
- `message` / `detail_json`
- `demand` / `supplier` / `order`（可选关联）

## 三、五阶段业务与代码映射（PR → PO）

| 阶段 | 业务动作 | 项目中的实现 |
|------|----------|----------------|
| 1. 需求申请 (PR) | 使用部门提交「买什么、为什么买」 | **PlannerAgent**：`parse_and_create`（IM）解析指令写入 `Demands`，状态 `待规划` |
| 2. 内部预审 | 部门真实性与预算可用性 | **Business_Rules**：`PlannerAgent.run()` 在 `待规划→待辩论` 前执行 `_prescreen_budget_before_debate`（预算上限等）；主管人工可在表中把关 |
| 3. 寻源比价 (Sourcing) | 多供应商 QCDSR / 辩论 | **SourcingAuditorAgent**：`run_audit_debate`（Top-K + LLM 辩论 + 降级），产出推荐供应商与摘要 |
| 4. 最终审批 (Approval) | 财务/高管对选型终审并授权 | **HITL**：飞书 interactive 卡片（`MULTI_STAGE_APPROVAL=true` 时：待主管审批 → 待采购确认 → 待运输审批；`Personnel` 匹配各环节 open_id） |
| 5. 订单执行 (PO) + 物流 | 下 PO、跟踪在途 | **SourcingAuditor / WS**：最后一环「运输审批」通过后写 `Orders`；**TrackerAgent** 按编排周期轮询更新 `logistics_status`（表内跟单，不对物理节点做额外审查）；**异常**时审计上报并写入关联需求 `notes`（非真实承运商对接） |

## 四、Agent 角色设计（与实现对齐）

### 4.1 PlannerAgent（需求规划员）
- **职责**：PR 结构化；编排 tick 中将 `待规划` 解析并推进至 `待辩论`（若 Business_Rules 预算预审失败则保持 `待规划` 并写 `notes`）
- **输入**：`Demands.source_instruction`
- **输出**：更新需求字段与状态；审计日志

### 4.2 SourcingAuditorAgent（选型审计官）
- **职责**：阶段 3 寻源辩论；阶段 4 推送/重发审批卡片；阶段 5 在「运输审批」通过后创建订单（与 WS 卡片回调协同）
- **输入**：`recommended_suppliers` 或按 `category` 匹配 `Suppliers.main_business`
- **输出**：辩论记录、需求状态在审批链上迁移、最终 `Orders` 记录

### 4.3 TrackerAgent（物流追踪员）
- **职责**：对已生成订单做**跟单轮询**：确定性推进 `待发货→运输中→已送达`（在途需多次编排扫描）；**不**对物理状态做人工审查环节。订单若被标为 `异常`（业务录入或外部同步），则**异常上报**（`Audit_Logs` + 关联 `Demands.notes` + 日志），**不连接真实物流 API**
- **输入**：`Orders.logistics_status`、`exception_reason`、订单关联 `demand`
- **输出**：订单字段更新；正常跟单与异常均写审计日志

### 4.4 StrategyAgent（采购策略分析师）
- **职责**：聚合需求与订单数据，生成效能与风险摘要
- **输入**：全量 `Demands`、`Orders`（分页扫描）
- **输出**：KPI 类结果与 `Audit_Logs`

## 五、业务流程设计（状态触发型，简图）
```text
[1 PR]  IM / 表：待规划
           │  Planner.run（含 Business_Rules 预算预审）
           ▼
[3 寻源] 待辩论 ──run_audit_debate──► 待主管审批 …（多卡 HITL）… ──► 已下单
           │                              │
           │                              ├ 待采购确认（卡片含供方/需求方对接信息）
           │                              ├ 待运输审批
           │                              └ 运输通过 → 写 Orders
           ▼
[5 执行] TrackerAgent：Orders.logistics_status 编排跟单（待发货→运输中→已送达）；异常则上报（日志+审计+需求备注）

定期：StrategyAgent KPI
```

## 六、技术架构
```text
主程序入口：main.py (AgentOrchestrator)
    ├─ Agent层：Planner / SourcingAuditor / Tracker / Strategy
    ├─ 数据访问层：FeishuBitableToolbox (requests + token缓存 + CRUD + 429重试)
    └─ 配置层：config.py (.env + 状态枚举 + 表ID)

外部系统：
飞书多维表格 OpenAPI（Demands / Suppliers / Orders / Audit_Logs）
```

## 七、部署与运行说明

### 7.1 环境准备
1. Python 3.10+
2. 安装依赖：`pip install -r requirements.txt`

### 7.2 配置说明
1. 复制 `.env.example` 为 `.env`
2. 填写：
   - `FEISHU_APP_ID`
   - `FEISHU_APP_SECRET`
   - `BITABLE_APP_TOKEN`
3. 确认 `config.py` 中 `TABLE_IDS` 对应当前 Base 的 4 张表

### 7.3 初始化与运行
1. 建字段（按 schema）：`python script/sqlinit.py`
2. 注入测试数据：`python script/inject_mock_data.py`
3. （可选）清理需求仅保留单条：`python script/clean_demands.py`
4. 启动编排器：`python main.py`

## 八、当前实现要点与后续扩展

### 8.1 当前实现要点
- 鉴权：`tenant_access_token` 自动缓存与过期刷新
- 健壮性：HTTP 429 指数退避重试
- 审计：统一 `log_to_audit_table()` 记录 Agent 操作
- 关联字段：支持 Link 字段写入与读取规范化

### 8.2 后续扩展建议
- 对接真实价格引擎与评分模型（替换当前简化策略）
- 引入 SLA 与交期偏差分析（提前预警）
- 增加飞书消息通知与异常工单自动派发
- 输出可视化看板（按部门/品类/供应商维度）
