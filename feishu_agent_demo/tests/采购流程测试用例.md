# 采购流程测试用例（与多维表格表单对齐）

本文档与 `script/sqlinit.py` 中的 **Demands / Suppliers / Orders / Audit_Logs / Personnel / Debate_History** 字段及选项一致；`.env` 中列名若与默认不同，以实际配置为准。

---

## 1. 表单速查（验收字段）

### 1.1 Demands（采购需求表）

| 字段 | 类型 | 与流程相关说明 |
|------|------|----------------|
| `demand_code` | 文本 | 主字段；IM 可用 `触发审批 DEM-xxx` 解析（`DEMAND_FIELD_DEMAND_CODE`） |
| `source_instruction` | 文本 | Planner 写入原始指令；编排 `run()` 读取 |
| `category` | 单选 | 选项含：原材料、辅料、包装、备品备件、设备、服务、其他；**审批人 Personnel.managed_categories 需能匹配** |
| `item_name` / `quantity` / `budget_amount` 等 | — | 卡片展示与 LLM 抽取 |
| `status` | 单选 | **待规划 → 待辩论 → 待审批 →（卡片通过）已选型/已下单** 等 |
| `recommended_suppliers` | 关联 Suppliers（多对多） | `run_audit_debate` 写入最终推荐；**重发卡片**依赖此关联 |
| `notes` | 文本 | 辩论摘要；**重发卡片**展示理由 |

### 1.2 Suppliers（供应商库）

| 字段 | 类型 | 说明 |
|------|------|------|
| `main_business` | 多选 | 与 Demands.`category` 做包含匹配，决定辩论候选 |
| `supplier_name` / `credit_score` / `quality_score` / `cost_score` 等 | — | 辩论与降级选型 |

### 1.3 Orders（采购订单表）

| 字段 | 说明 |
|------|------|
| `demand` | 一对一关联 Demands |
| `supplier` | 多对一关联 Suppliers |
| `logistics_status` | 待发货 / 运输中 / 异常 / 已送达（Tracker 按 tick 跟单；`异常` 触发上报） |

### 1.4 Personnel（负责人表）

| 字段 | 说明 |
|------|------|
| `role` | 含 **Approver**（代码按「主管 / approver」匹配） |
| `feishu_open_id` | 审批卡片接收人；空则回退 `MOCK_PERSONNEL_FEISHU_OPEN_ID` |
| `managed_categories` | 多选；需与需求 **category** 有交集，或表中为「全品类」类扩展（代码支持全品类 token） |

### 1.5 Debate_History（若已配置 `TABLE_ID_DEBATE_HISTORY`）

| 字段 | 说明 |
|------|------|
| `demand_id` | 关联 Demands |
| `agent_identity` / `stance` / `argument_content` | 辩论条目；若租户将 `agent_identity` 设为严格单选，需与机器人写入值一致，否则可能写库失败 |

## 2. 测试前置（数据与环境）

| 编号 | 项 | 要求 |
|------|----|------|
| P-01 | 进程 | 启动 `python main.py`（编排 + IM WebSocket） |
| P-02 | 机器人 | 测试账号与机器人 **单聊** 已建立 |
| P-03 | 供应商 | 至少 1 条 Suppliers：`main_business` 包含某条需求将使用的 **category**（如「设备」），`status`=启用 |
| P-04 | 审批人 | Personnel：`role`=Approver，`feishu_open_id` 为真实用户；**managed_categories** 与测试需求 **category** 可匹配；或配置 `MOCK_PERSONNEL_FEISHU_OPEN_ID` |
| P-05 | LLM | `USE_MOCK_LLM` 与网络按环境选择；辩论耗时可 >1 分钟 |

## 3. 功能测试用例（IM + 表）

### 3.1 主链路：聊天全流程

| 用例ID | 标题 | 前置 | 操作步骤 | 预期（表 / 行为） |
|--------|------|------|----------|-------------------|
| TC-IM-01 | 录入需求 | P-01～P-03 | 私聊发送：`采购测试物料A，数量10，预算5000元，品类选设备`（或等价自然语言） | Demands 新增 1 条：`status`=`待规划`；`source_instruction` 非空；回复含 `record_id` |
| TC-IM-02 | Planner 推进待辩论 | TC-IM-01 后 | 等待 ≥1 个编排 tick（默认 `POLL_INTERVAL_SECONDS`） | 同条 Demands：`status`=`待辩论`；Audit_Logs 有 Planner 更新记录 |
| TC-IM-03 | 触发审批（record_id） | TC-IM-02 | 发送：`触发审批 recvxxxxxxxx`（替换为真实 record_id） | `status`=`待审批`；`recommended_suppliers` 关联 1 个供应商；`notes` 有摘要；Debate_History 或 Audit_Logs 有辩论痕迹；**审批人飞书收到 interactive 卡片** |
| TC-IM-04 | 触发审批（demand_code） | 表中该条 Demands **`demand_code` 已填**（IM 创建默认可能为空，需手工或公式补全）且 `待辩论` | 发送：`触发审批 DEM-TEST-01` | 同 TC-IM-03（按 `demand_code` 解析到正确 record） |
| TC-IM-05 | 待审批重发卡片 | TC-IM-03 后卡片未收到或失败 | 再次发送同一句 `触发审批 …` | 不报错「须为待辩论」；回复含「重发」类说明；审批人侧收到卡片或日志含 Feishu code/msg |
| TC-IM-06 | 重复触发（待审批） | 同 TC-IM-05 | 第三次 `触发审批` | 仍为重发逻辑；不重复跑辩论覆盖订单（不重复下单） |

### 3.2 卡片回调（飞书 UI，非纯文本）

| 用例ID | 标题 | 前置 | 操作 | 预期 |
|--------|------|------|------|------|
| TC-CARD-01 | 同意下单 | TC-IM-03 成功收卡 | 审批人点「同意下单」 | Orders 新增：`demand` 指向该需求，`supplier` 为推荐供应商；Demands `status` 进入已下单（与代码 `BusinessStatus.ORDER_PLACED` 一致）；`notes` 含审批通过说明 |
| TC-CARD-02 | 驳回 | 待审批且已收卡 | 点「驳回重选」 | Demands `status`=`已驳回` |

### 3.3 负例与边界（表状态）

| 用例ID | 标题 | 前置 | 操作 | 预期 |
|--------|------|------|------|------|
| TC-NEG-01 | 缺参数 | — | 发送：`触发审批`（无 ID） | 机器人提示补充 `recv…` 或 `DEM-…` |
| TC-NEG-02 | 错误 demand_code | — | `触发审批 DEM-NOT-EXIST` | 提示未找到需求编号 |
| TC-NEG-03 | 待规划直接审批 | Demands 单条 `status`=`待规划` | `触发审批` 该条 | `run_audit_debate` 拒绝（须先 `待辩论`）；回复说明状态不符 |
| TC-NEG-04 | 无候选供应商 | Demands `待辩论` 且 category 与所有 Suppliers.`main_business` 不匹配 | `触发审批` | 辩论跳过或失败路径符合日志；`status` 不按成功挂起待审批（以当前 `sourcing_auditor` 实现为准） |
| TC-NEG-05 | 无审批人 open_id | Personnel 无匹配且未配 MOCK | 完成辩论 | `status` 可为 `待审批` 但日志提示未推送卡片 |

## 4. 与 Personnel 品类对齐的检查项

- Demands.`category` 单选值来自：`原材料、辅料、包装、备品备件、设备、服务、其他`。
- Personnel.`managed_categories` 含：`电子料、光学件、原材料、…` 等。  
- **建议**：测试用需求明确写「品类」为 **原材料** 或 **设备** 等与 Personnel 多选 **有交集** 的值；否则审批人匹配失败，仅走 MOCK。
